FIELD GUIDESONIC-PI

Sonic Pi / SONATA integration

Use Sonic Pi as the musical clock and control source while AVTranslator performs the image.

01 — What the connection does

SONATA Expanded sends transport, bar-clock, scene, macro, cue and heartbeat messages. AVTranslator receives them at the versioned /eli_lab/v1 OSC namespace. Sonic Pi remains responsible for audio playback; AVTranslator uses musical intent to change visual scenes and parameters.

The M4 sender is installed at musical control points only. It does not instrument the 93 synth/drum loops.

02 — Sender configuration

At the top of SONATA_expanded.rb, verify:

  • $sp_av_enabled = true — set false for audio-only rehearsal.
  • $sp_av_host = "127.0.0.1" — AVTranslator address.
  • $sp_av_port = 57121 — match the receiver port shown in AUD / CTRL.

Same-computer use defaults to loopback. For remote Sonic Pi, bind AVTranslator to its reachable LAN IPv4 address and set $sp_av_host to that address. Do not use 127.0.0.1 for a remote sender.

03 — One-button autonomous connection

  1. Prepare the composition. In AUD / CTRL choose System Loopback for actual audio-band/onset analysis, or use Sonic Pi macros when local capture is unavailable.
  2. Verify receiver address and port. Use COPY SONATA SETTINGS to copy them into the patch.
  3. Press PERF MODE. AVTranslator starts or reuses the OSC receiver, starts requested local audio capture, installs default modulation curves/routes when required, and arms automation.
  4. Run SONATA_expanded.rb in Sonic Pi.
  5. The first transport/start or accepted bar-clock packet moves AVTranslator from ARMED to LIVE. Scenes, phrase cues and macro values then drive visual changes.
  6. Stop SONATA to stop automation. Press STOP PERF MODE to release resources owned by the mode.

04 — Musical clock and form

01

TEMPO

92 BPM

 02

METER

4 beats per bar

 03

FORM

384 bars · approximately 16 minutes 42 seconds

 04

SCENES

16 scene changes, including the final end marker

The bar clock increments sp_b_count, cues sp_b, then sleeps for four beats. Scene changes update sp_sc and sp_int, then cue sp_sc_change. The synchronized macro loop updates energy, cutoff and phrase index. OSC bar_index is 1-based; the initial pre-clock scene marker uses bar 0.

05 — OSC protocol

Every event begins with a session ID string and positive sequence number. Sequence numbers increase across all event types for one patch run. Restarting the patch creates a new session ID.

Address Event Purpose
/transport/start transport.start BPM and beats per bar
/transport/stop transport.stop Stop transport
/transport/tempo transport.tempo Update BPM
/clock/bar clock.bar 1-based bar, BPM and meter
/scene/select scene.select Scene ID, intensity and bar
/scene/intensity scene.intensity Normalized scene intensity
/macro/set macro.set Registered macro name and 0–1 value
/cue/trigger cue.trigger Named cue
/source/heartbeat source.heartbeat Sender heartbeat

Built-in macro names are chaos, density, depth, decay, pressure and fragment. The existing patch also sends normalized energy and cutoff. Values are clamped/validated in the receiver; unknown names and out-of-range values are rejected.

06 — Receiver safety

  • Default bind is loopback; other interfaces require explicit selection.
  • Only known addresses, exact argument counts, strict OSC types and safe numeric ranges are accepted.
  • A bounded replay history rejects superseded sessions and duplicate/out-of-order sequences.
  • Input is rate-limited to 60 messages/second by default.
  • The OSC worker submits validated events to a queue; Qt widgets, composition state and OpenGL resources are not touched from the worker.
  • A stale sender can be recovered by restarting SONATA with a fresh session ID.

07 — Rehearsal checklist

  1. Start AVTranslator, press PERF MODE and confirm the receiver is listening on the intended address/port.
  2. Run SONATA and confirm ARMED changes to LIVE.
  3. Check BPM 92, bar positions 1–384, scene changes, energy/cutoff values and phrase cues.
  4. Restart SONATA and confirm a fresh session is accepted while delayed packets from the old session are rejected.
  5. Press STOP PERF MODE and confirm Sonic Pi audio continues. Re-arm before the next run.

Protocol and sender insertion are implemented. The full 384-bar performance still requires manual rehearsal on the target Sonic Pi and AVTranslator computers.
